# Public release checklist

- [ ] Move or mirror only the intended `evidence-core` subtree into a public repository.
- [ ] Run secret, license, and dependency scans before first push.
- [ ] Confirm full Apache-2.0 license text, NOTICE, authorship, governance, security policy, and contribution guide.
- [ ] Preserve original Git authorship; do not rewrite or fabricate dates.
- [ ] Add branch protection, required tests, dependency updates, and signed release tags.
- [ ] Publish v0.1.0 source and wheel; archive the exact release with a durable DOI when available.
- [ ] Publish the preprint and link the immutable source release.
- [ ] Run benchmark repetitions and publish every raw result plus environment metadata.
- [ ] Ask one unaffiliated person to reproduce verification from the README.
- [ ] Open public issues for known limitations from the paper.
- [ ] Enable a vulnerability-reporting route and define response targets.
- [ ] Keep private keys, source exports, real identity data, PHI, and customer material out of the repository.
