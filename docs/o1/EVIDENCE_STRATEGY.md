# Evidence strategy

## Claim classes

| Class | Acceptable proof | Current state |
| --- | --- | --- |
| Original technical contribution | public code, releases, paper, design history, independent adoption | implementation ready; adoption not established |
| Critical role | contracts, org letters, authored decisions, measurable outcomes | organization-specific proof required |
| Authorship | published technical paper, repository authorship, citations | preprint ready; publication/citations pending |
| Judging others | documented review panels or formal expert review activity | not established |
| Press or published material | independent publication principally about the work/person | not established |
| High remuneration | contracts, payroll, market comparisons | private financial proof required |
| Awards | competitive award rules and official result | not established |

## Evidence lifecycle

1. Capture the original artifact and stable public URL.
2. Record whether it is first-party or independent evidence.
3. Hash it and, for important bundles, create a signed evidence pack.
4. Record permission and confidentiality constraints.
5. Link the artifact to one narrowly worded claim.
6. Have a second person verify the claim against the artifact.
7. Ask qualified immigration counsel to select and contextualize evidence.

## Twelve-week execution order

Weeks 1–2: publish the core, tag v0.1.0, archive the release, publish the preprint, and run CI.
Weeks 3–4: obtain one independent benchmark reproduction and two methodology reviews.
Weeks 5–8: run two scoped pilots with pre-agreed measurements and signed outcome reports.
Weeks 6–10: submit talks and technical articles using the included abstract package.
Weeks 9–12: publish aggregated results, request expert letters based on firsthand review, and assemble counsel-ready exhibits.

## Guardrails

- “Measured” means raw results and environment metadata are preserved.
- “Independent” means the evaluator is not the author and disclosed conflicts are recorded.
- Modeled savings are never relabeled as observed savings.
- Synthetic healthcare data is never described as patient data or clinical validation.
- A cryptographic signature proves key possession and content integrity, not factual truth or signer identity without a trust anchor.
