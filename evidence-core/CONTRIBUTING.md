# Contributing

1. Open an issue describing the problem, security impact, and proposed behavior.
2. Add tests and an Architecture Decision Record for protocol or trust-model changes.
3. Use your real Git identity and certify that you have the right to contribute the work.
4. Do not submit customer data, credentials, PHI, production logs, or third-party confidential material.
5. Include reproducibility instructions for benchmark changes.

By contributing, you agree that your contribution is licensed under Apache-2.0 and that the Git history is the authoritative authorship record.
